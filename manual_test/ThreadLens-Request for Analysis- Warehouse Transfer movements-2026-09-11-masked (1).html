Hi,

 

Some notes on Warehouse Transfers ahead of today’s call:

 

How does stock move from the InReceipt bucket to Free stock?

The Transfer involves an Inbound Task that need to be completed by a Radio Data System (RDS) operator. When this has been done and is fully processed the stock is moved from In Receipt to Free.

 

 

Could you please clarify the expected movements for a warehouse transfer as this is causing mis-alignment between Stock Master and Calidus?

a)) Warehouse Transfers are created by the EOD process. This creates Transfer Out and Transfer In tasks that need to be actioned using the Radio Data System (RDS).

 

Transfer Out Completion i.e. move stock from the source warehouse stocking location to the warehouse transfer location.

A “MOVE” stock movement is created to confirm the movement of stock from a stocking location to the transfer location.

Source Free reduced

Source In Transit Issued (WP_ISS_INTRANSIT_SU) increased

Destination In Transit Received (WP_REC_INTRANSIT_SU) increased

 

Transfer In Collection i.e. pick up of stock at the warehouse transfer location.

“XFER” stock movements are created for both the source and destination warehouses.

Source WP_ISS_INTRANSIT_SU decreased

Source Physical decreased

Destination WP_REC_INTRANSIT_SU decreased

Destination Physical increased

Destination In Receipt increased

 

Transfer In Deposit – move of stock from the warehouse transfer location to the destination stock location.

“XFOT” stock movement is created for the source warehouse.

“XFIN” stock movement is created for the destination warehouse.

Destination In Receipt decreased

Destination Free increased

 

 

b)) Warehouse Transfers can also be completed by using a back office screen (w916a01t).

The stock movements and inventory updates are completed within a single transaction.

“XFER” stock movements are created for both the source and destination warehouses.

“XFOT” stock movement is created for the source warehouse.

“XFIN” stock movement is created for the destination warehouse.

Source Physical decreased

Source Free decreased

Destination Physical decreased

Destination Free decreased

Hi,

 

Notes on PUTA i.e. Putaway Adjustment.

 

When it is an increase adjustment (i.e. more to be putaway than expected - KM_STATUS = 1) then Physical and Free are increased.

 

When it is a decrease adjustment (i.e. less to be putaway than expected - KM_STATUS = 0) then Physical and In Receipt are decreased.

Hi,

 

On the last call we discussed the need to distinguish Warehouse Transfers actioned from the Back Office versus those from RDS.

 

Further review of the XFER, XFIN and XFOT records shows that there is currently a distinguisher.

 

The Back Office screen enforces the mandatory entry of a Reason Code for the transfer.

 

This is held on the SME_REASON_CODE column.

 

The Reason Code is not prompted in RDS and so RDS warehouse transfer movements have a blank value in the SME_REASON_CODE column.

 

Hence, no code changes are needed, as Back Office warehouse transfers can be distinguished by a non-blank entry in the SME_REASON_CODE column.
